# Phase 1 — implemented controls, evidence and remaining blockers

## Decision

Phase 1 implementation is complete. Full production approval remains **withheld**. Passing software tests does not establish forecasting accuracy. G_hybrid remains the sole public forecasting family; no production weights were fitted or replaced.

The implementation was prepared separately from the user's dirty working tree, against GitHub main `e311c0884426a5fdde2ce1f2f0bf53dff006670b`. The current release checksum file identifies the candidate source/model bytes. Exact CI commit binding is generated by the verification workflow, and its result must be read separately from this local report.

## What changed

- All eight decision/calendar horizons now have conservative provisional outcome matching, independent ledger-boundary validation and horizon/artifact/evidence-specific calibration readiness.
- Calendar endpoints remain tied to their recorded forecast origin, including a delayed ledger insertion. Missing observations do not become zero changes. Official and supplier outcomes remain separate.
- Independent 80% and 90% conformal order statistics use only earlier matured labels, deduplicate repeated targets and conservatively exclude overlapping information intervals. Numerical bands are withheld until both sample and chronological coverage requirements are met. No probabilities are manufactured.
- Anchored scenarios add the structural input change to the recorded price. The illustrative old scaffold remains available, with USD-linked imports, LBP charges, VAT and an unexplained reconciliation residual distinguished.
- Current release integrity is separate from immutable historical manifests. Original source bytes and the exact compressed development input are preserved where recoverable; saved metrics and model predictions still undergo replay checks.
- GitHub Actions is the durable writer. Owner refreshes dispatch a workflow; without the server-side dispatch secret they fail closed rather than writing ephemeral cloud databases. Scheduled raw captures and their database references are committed together even when the run later fails strict checks.
- Structured health distinguishes feeds, anchor, forecast age, calibration, integrity, release and refresh status. A research-model label cannot conceal an integrity failure.

## Actual verification

The final local production-verification command ran the complete existing fuel suite: **316 passed, zero pytest warnings**. Current release identity, structural artifact audit, forecasting artifact audit, validation artifact replay/hash-chain audit and dependency compatibility passed. Strict operations integrity **failed**, so the command correctly returned exit code **1**. Full command output is preserved in `reports/operations/final_verification.json`.

Baseline verification had 292 passing tests and failed forecasting/validation release-hash checks and strict operations integrity. The new separation fixes the release-hash mismatch without rewriting either historical manifest. It does not claim recovery of all older scientific source versions.

## Evidence coverage and recovery

The reviewed database contains 1,372 dated domestic records spanning 2008-01-02 through 2026-11-17 and ten stored market series. These are dated records, not 1,372 certified complete official decrees.

Seventeen missing original capture files were recovered with exact SHA-256 matches. **69 original files remain missing**, and no present file was found corrupt. Every missing path, expected checksum, capture ID, URL and retrieval time is in the updated gap catalog. No old capture was recreated from a new download or removed from the database.

Twenty-eight needed historical source versions were recovered and archived by their original SHA-256. **Twelve older training/evaluation source versions remain unrecovered**; their original hashes remain recorded in the frozen references. Model bytes, historical run manifests, immutable forecasts and ledger hash-chain triggers are unchanged. Report generation only appends eligible evaluations/match attempts; it does not issue forecasts.

## Prospective evidence and availability

There are zero scored official next-decision outcomes and one independent provisional next-decision outcome, with absolute error 13,016 LBP and one correct direction. One outcome is not an accuracy estimate. Four matching forecast rows refer to this outcome; repeated refreshes do not make four independent cases.

All eight active-artifact calibration readiness states remain withheld because independent matured residuals and chronological coverage tests are insufficient. The minimum policy is 30 calibration cases plus 20 subsequent nonoverlapping chronological coverage tests per horizon, artifact, anchor cohort and outcome-evidence stratum. This can take months; long horizons require more elapsed time.

The report counts 27 complete stored refresh attempts per horizon: 14 abstentions each; 13 Hybrid issuances for next-decision/seven-day and 10 for the other horizons. Remaining issued cases used older families. These are attempt counts, not uptime percentages or independent decisions. Historical abstention reasons include conflicting/unconfirmed anchors and missing domestic-change inputs; reasons may overlap. No old prediction is rewritten to improve these counts.

## Scenario reconciliation

Using the stored product proxy of 97.776 USD/bbl and the explicitly assumed May 2025 scaffold, the original unanchored reconstruction is about 1,894,045 LBP/20 L, versus the latest eligible recorded anchor of 2,343,000 LBP on 2026-11-17.

- Unchanged anchored inputs return exactly **2,343,000 LBP**, with zero change; this was also checked in the running browser calculator.
- Changing pricing FX from 89,500 to 100,000 LBP/USD, all else held as specified, returns about **2,505,003 LBP**.
- Increasing the product input by 10 USD/bbl returns about **2,467,972 LBP**.

These are hypothetical sensitivities, not forecasts or probabilities. USD display conversion remains a separate assumption. The residual is not relabelled as an official tax or margin.

## Unresolved blockers and Phase 2 handoff

1. Recover the remaining 69 original capture files, or retain the failed audit and documented loss. A new download cannot replace their original provenance.
2. Preserve the 12 missing historical source-version gaps; historical training reproducibility is incomplete.
3. Accumulate enough independent, timely outcome evidence for each horizon. Current code supports calibration but current evidence does not support released bands or probabilities.
4. Verify exact-commit CI evidence and public deployment separately. The local checksum attestation is explicitly not a deployed-commit attestation or digital signature.
5. Configure the server-side `LEBANON_FUEL_ACTIONS_TOKEN` if owner-triggered workflow dispatch is required. No credential or permission was provisioned; scheduled refreshes remain available.
6. A current official formula, licensed Mediterranean gasoline data, complete official publication/effective clocks and a verified dated fiscal-regime map remain unresolved. Proxy/scenario labels remain mandatory.

Phase 2 should consume the structured health and horizon-readiness contracts, improve the consumer presentation and recovery guidance, then add permanent forecast links and optional opt-in alerts. It must not relax the failed evidence checks, fabricate confidence, change weights automatically or imply that UI polish establishes predictive skill.
